## 问题排序

P1：阻断核心使用，应优先修复。P2：明显影响正常操作。P3：体验优化。

| 优先级 | 问题 | 证据级别 | 用户影响 |
|---|---|---|---|
| P1 | 正常沙盒下，新选择的 MP4 / MKV 打不开 | 三个文件实际复现 | 最基本的“打开就播”失败 |
| P1 | 重启续播黑屏，时间仍推进 | 独立构建两次启动观察，退出重启再次复现 | 用户以为文件损坏或播放器卡死 |
| P2 | 暂停时跳转不刷新画面 | 实操与代码一致 | 无法暂停找镜头，时间和画面不对应 |
| P2 | 到达片尾仍是播放中，再播放不从头开始 | 跳到片尾路径实测，代码核对 | 结束状态不清晰，重播需要手动回到开头 |
| P2 | 普通窗口焦点下左右方向键不跳转 | 多次实操 | 常用五秒快进/后退失效 |
| P2 | 关窗后播放继续推进 | 实际观察；属于体验决策 | 用户关掉窗口后错过内容 |
| P2 | 流畅档自动降级不反馈实际状态 | 代码确认，未测定本轮实际降级状态 | 选中“高质量/快”不能证明当前确实生效 |
| P3 | 无应用内音量/静音入口；帮助文案暴露实现名称 | UI 与代码检查 | 缺少常用控制，“IFRNet / Fast A / 源分辨率直通”对普通用户难懂 |

## 1. 新视频打不开

1. 启动独立构建的正常沙盒应用。
2. 按 `⌘O`，在系统文件对话框中选择上述 MP4 或 MKV。
3. 点击“打开”。
4. 应用显示“无法播放：未能打开文件……”，没有进入该视频。

三个文件均失败，横跨系统解码和 FFmpeg 两条路径，因此不能归类为“某个 MKV 编码不支持”。错误发生后原有 FLV 仍保留。

**定位线索：** `Sources/Playback/PlaybackEngine.swift:82` 在解码前先创建书签；`Sources/Legal/FileOpening.swift:17` 只传入 `.withSecurityScope`，没有只读书签选项。书签可理解为 PHP 应用保存的文件访问凭证；这里需要它与沙盒的只读授权一致。当前错误文案不是 `SourceError.decodeFailed` 的文案，旧视频也没有被停掉，优先怀疑书签创建步骤。**这是高可信排查方向，尚未通过修复前后对照证实根因。**

现有 `Tests/FileOpeningTests.swift:19` 使用应用临时目录文件，无法覆盖用户从 Downloads 选择文件时的授权边界。

建议验收：正常签名沙盒下，首次打开、Finder 拖入、退出后续播都成功；不能靠扩大目录权限通过。

## 2. 重启续播黑屏

1. 使用已有 FLV 续播记录启动，时间显示约 07 分钟并继续增加，画面全黑。
2. 暂停、继续、关闭 Anime4K，仍未立即恢复画面。
3. 通过进度控件回到 00:00 再播放，视频恢复出画。
4. 正常播放后在约 04:09 暂停，`⌘Q` 退出，再启动同一构建。
5. 续播时间推进到 04:24，画面再次全黑；回片头又恢复。

因此不是截图工具无法捕获视频：同一个窗口、同一工具能捕获从片头播放的正常画面。

**定位范围：** `PlaybackEngine.swift:174` 的恢复时间分支，以及 `PlaybackSession.swift` 中 seek、音频时间基准、待显示画面队列的配合。这里类似 Vue 已经更新了播放时间状态，但画布没有得到可显示的目标数据。**本轮未确定是哪一处导致黑屏，不直接归因于 Anime4K 或解码器。**

建议验收：至少在不同中段位置退出重启，目标时间附近能显示首帧，再连续播放；同时验证不同文件及两条解码路径。

## 3. 暂停定位只有时间变化

在 FLV 约 00:25 暂停，通过进度控件跳到 02:21，时间与滑块已更新，画面仍是原镜头；恢复播放后才更新为目标位置画面。

此处用无障碍进度控件触发跳转，以避免鼠标拖动工具的干扰；它能实际改变后续播放位置。

**代码直接对应：** `PlaybackSession.swift:267` 在暂停时不读取新画面，`:208` 又只在播放中绘制。类似 Vue 更新了表单值，却没有刷新用于预览的组件。

建议暂停 seek 完成后显示目标附近一帧，并保持暂停。不要为了刷新画面偷偷开始播放。

![暂停跳到 02:21，仍保留原画面](/Users/wh/workspace/hao-player/docs/reports/2026-09-09-experience-assets/paused-seek.png)

## 4. 片尾状态与重播

暂停后将进度调到 `19:25 / 19:25`，再播放，按钮变为“暂停”，时间不再推进。之后再次暂停、播放，仍停在片尾，没有重播。

**代码直接对应：** `PlaybackSession.swift:273` 收到文件结束只停止解码循环，没有把播放状态切到结束；`play()` 也没有片尾回零逻辑。

本轮实际覆盖的是“跳到片尾再播放”，没有从头连续看完 19 分钟。自然结束会经过同一段结束处理代码，但仍需单独回归。

建议明确结束状态；在队列播放完后停止时钟，主按钮变为播放/重播，并支持一次点击从头开始。

## 5. 左右键与关窗行为

**左右键：** 暂停在 10:17，多次左键未改变时间；重启后暂停在 04:24，依次右、左、右，时间仍不变。此时焦点是普通播放器窗口，空格暂停/继续正常。`PlayerScreen.swift:97` 虽注册了方向键处理，但焦点接收路径需要核查，可理解为 Vue 键盘事件监听没有收到当前焦点发出的事件。

**关窗：** 播放至约 03:53 时 `⌘W`，随后 `⌘0` 可以恢复窗口；时间继续推进，随后暂停读数已到 04:09。`PlayerScreen.swift:89` 在视图消失时只保存续播，没有暂停。

关窗继续播放不是崩溃，但对于单窗口视频播放器容易造成误解。建议默认暂停；如果产品决定允许后台播放，也应给出明确控制方式。

## 6. 增强开关不能证明实际效果

实际点选 Anime4K、快、高质量，全屏播放，未观察到即时崩溃，画面能继续更新。这只证明操作路径可用。

`InterpolationRuntime.swift:43` 会因耗时过长降级，`:60` 的顺序为高质量 → 快 → 关；`PlayerChrome.swift:61` 仍绑定用户选择的 `settings.interpolation`，没有展示运行中的实际档位。Anime4K 失败时也会切换到直通，而开关仍可显示开启。

这类似 Vue 表单仍显示“高质量”，实际执行状态已变成另一个值。建议区分用户选择与实际状态，降级时给出简短可理解提示。本轮没有用性能分析工具测量实际帧率、单帧耗时或插帧占比，**不能宣称快档或高质量档实时达标，也不能宣称本轮已发生自动降级。**
