# 高质量播放临时对象释放修复

已修复播放后台循环中临时对象积累的问题。每次读取、增强、输出入队放在独立自动释放池中，及时回收 Core ML / Core Image 的临时对象；显示队列和插帧上一帧仍持有需要的画面。未修改用户选择、算法或源分辨率。

| 验证 | 修复前 | 修复后 |
|---|---|---|
| 720p24 高质量单开 | 约 566 秒后停止更新；最后内存采样 33.66 GiB | 完成 600.07 秒；30 秒后 504.5–549.5 MiB，最后采样 526.0 MiB |
| 高质量 + Anime4K | 该轮未完成测量 | 完成 60.10 秒；30 秒后 730.3–744.7 MiB，应用正常退出 |
| 自动回归 | — | 59 项通过，0 失败，包含真实 GPU / 模型及快档五次创建销毁 |
| 构建 | — | 独立沙盒验收 Release 与普通产品 Release 均成功 |

两轮使用同一 720p 固定素材。复测使用 Apple Development 正常签名、沙盒开启的独立验收入口，实际运行产品解码、增强与屏幕呈现管线，没有 XCTest 注入权限。测试入口新增内存增长保护，30 秒后增长超过 2 GiB 即保留报告并退出失败，避免再次耗尽内存。

**内存修复已验证，高质量 48fps 目标仍未完成。** 本次实际显示 20.94fps，模型计算是主要耗时阶段。收尾时刷新率已为 ProMotion，复测开始未重新锁定 60Hz，因此此次帧率只用于诊断。双开只有一分钟证据；未将它称为十分钟稳定性通过。

完整阶段耗时、冷启动、真实补帧显示数、签名、测试日志与原始采样见 [增强验收记录](2026-09-09-enhancement.md) 和 [复测数据](2026-09-09-enhancement-evidence/after-frame-pool/summary.json)。修复前后的逐次内存数据均保留，可以复核。保留现有未提交修改，没有提交或发布。
