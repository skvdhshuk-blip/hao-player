# 高质量卡顿：性能定位与优化尝试

**本轮没有解决原生 IFRNet-S 的 720p24→48fps 持续目标。** 不把局部算子提速、短测或减少内存当作播放流畅性通过。以 v0.2.1（c1c0c49）为基线，原模型、源分辨率、半精度设置和失败行为保持不变。

## 已确认的瓶颈

- 实际后台解码循环中，退出自动释放池的平均耗时约 0.003–0.005ms；模型计算平均约 49–51ms。没有证据支持改成大批量释放能够解决当前卡顿，因此保留每轮释放，避免再次积累到几十 GiB。
- 正式签名、沙盒开启的应用采集了 Metal System Trace。在 10.714 秒采样跨度内，播放器 Compute 执行区间的并集约 9.375 秒（87.5%）。采样时为 ProMotion，后续 A/B 和最终持续测量固定为 60Hz。这是特定进程计算通道的执行覆盖率，不是理论 GPU 算力利用率；采样开销也不能混入未采样帧率对比。
- GPU 记录能看到 IFRNet_S 的 MPSGraphInference 实际执行；主要问题不是没有启用 GPU。

## 对照实验

固定内建屏幕 60Hz、960×540 点窗口、2× backing scale；同一 720p24 MKV，顺序运行，另一个播放器暂停。机器仍有其他后台任务，A/B/A 重测用来识别环境波动，不宣称实验室空闲基准。

| 版本 | 测量时长 | 显示 fps | 模型均值 | 10 秒后内存范围 |
|---|---:|---:|---:|---:|
| 原版本 A | 45.0s | 25.63 | 50.75ms | 502.4–509.5 MiB |
| 候选 B（缓冲池 + 模型提示 + 优先级） | 45.0s | 25.84 | 49.27ms | 472.8–475.6 MiB |
| 原版本 A 重测 | 45.0s | 26.66 | 48.66ms | 506.0–525.4 MiB |

B 的帧率落在两轮 A 的波动范围内，不能认定为流畅性提升。模型配置提示与调度优先级改动已撤回；保留缓冲区复用，最后另做持续验证。

| 实验 | 观察 | 处理 |
|---|---|---|
| 两帧特征提取合并 + 固定尺寸 | Python 短测约 50.9→47.4ms；组合实验无法将收益独归于合并，仍超过帧预算 | 未合入 |
| GPU 低精度累加 | 随机输入相对原输出 MAE 3.52/255，最大 176/255 | 不满足一致性要求，未合入 |
| 2/3 次推理批处理 | 每帧约 51ms，未发现明确吞吐改善 | 未合入 |
| 整模型 CPU + 神经网络加速器 | 编译错误及约 363–559ms 推理 | 未合入，产品没有启用此配置 |
| 最重卷积段单独使用加速器 | 局部约 31.4→19.6ms | 仅为局部实验，继续检查整链 |
| GPU → 加速器 → GPU 三段串联 | 完整约 47.8→50.9ms；随机输入 MAE 3.06/255、最大 145/255 | 收益被传递开销抵消且有额外误差，未合入 |
| 旧 neuralnetwork 导出后端 | 不支持当前 resample 算子的目标组合 | 未合入 |

所有数值均有 [本地证据目录](2026-09-10-quality-optimization-evidence/)。随机输入属于一致性压力样本，不等同于自然视频的主观画质评估。原始 1.5GB Metal trace 留在忽略的 build/hq-opt 内，没有上传或发布。

## 最终保留的改动

1. IFRNet 输入和裁剪输出使用 CVPixelBufferPool，复用已无人持有的缓冲区；最多缓存源尺寸与补边尺寸两类池。仍被显示队列持有的缓冲区不会回收复用。
2. 复用色彩空间对象，减少每帧重复创建。
3. 诊断新增临时对象释放、增强与释放合计；持续验收 P95 将释放开销计入。暂停、失败和旧会话的回调不能污染这一统计。
4. 新增保留输出不被后续帧覆盖、释放计数在暂停/旧会话时不累计的回归。

合成运动补帧与 v0.2.1 保存的输出逐像素一致（MAE 0，最大误差 0）。模型文件未改动，没有降低源分辨率、切换算法或更改精度。

## 最终持续验证

61 项自动回归通过，0 失败，真实 GPU 和模型测试执行。普通 Release 与独立沙盒验收构建分别验证，未改模型文件。

[最终原始数据](2026-09-10-quality-optimization-evidence/final-600s/summary.json)。最终版本只包含缓冲池与计时改进；不包含此前候选 B 的模型提示和调度优先级。不能拿十分钟结果与 45 秒短测的帧率差直接宣称提速。

原生 IFRNet-S 高质量流畅性仍未完成。本轮测试过的合批、配置和拆分方法不足以达成目标；需要进一步优化模型执行结构或重新评估模型选型，不能继续用更多缓存掩盖持续吞吐不足。未提交或发布新版本。

收尾：已恢复 ProMotion，并恢复测试前暂停的视频播放。改动留在工作区，普通产品 Release 构建和签名验证通过；未提交、推送或发布。

后续交付：用户决定隐藏高质量入口，只保留关 / 快；上述缓冲池、计时改进和证据纳入 0.2.3，详见 [发布记录](2026-09-10-release-0.2.3.md)。高质量性能未达标的结论保持不变。
